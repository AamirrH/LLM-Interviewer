# B0 — Project skeleton and settings

Status: complete; combined gate passed on 2026-09-21. Branch: `batch/b00-project-settings`. Release tag: `b00-project-settings`. Source: PRD §15.5 B0.

## Frozen scope

- Includes: React + TS + Vite app shell, routing, storage layer (IndexedDB), settings page, local key storage (BYOK), data export/import/delete-all, test runner and CI-style local check script, E2E harness.
- Not included: any LLM call, any interview UI.
- Done when: app runs locally and builds to a static bundle; settings survive reload; delete-all wipes everything; the smoke E2E runs green.

## Plan

1. Establish the toolchain, static routes, and local validation commands.
2. Write storage tests first; implement validated settings and versioned backups in IndexedDB.
3. Build accessible settings, provider-key controls, and export/import/delete flows.
4. Exercise the production build in a browser, refine errors and responsive layout, record the gate, and merge/tag.

## Test list

- Default settings have recording and autocomplete off; keys are absent.
- Saved preferences and keys survive a new database connection.
- Invalid settings and unsupported/corrupt backups are rejected without modifying data.
- Backups exclude credentials by default; importing preserves existing credentials.
- Backup round trip restores preferences; replacement is transactional.
- Delete-all clears every application table, including keys.
- Browser smoke covers navigation, settings reload, key save/removal, export/import, deletion, invalid files, and offline use after loading.
- Static build, type check, lint, unit tests, and E2E pass via `npm run check`.
